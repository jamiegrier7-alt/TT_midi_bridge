# Firmware Refactoring Todos

## macro-3.ino (Adafruit MacroPad Firmware)

### Structure & Architecture
- [ ] Refactor macro-3.ino into modules
  Description: Separate hardware I/O, state machines, rendering, and serial parsing into distinct components. Currently all mixed in loop() and event handlers.

- [ ] Break loop() into smaller functions
  Description: Main loop is 60+ lines mixing keypad, encoder, serial reading. Split into updateKeypad(), updateEncoder(), updateSerial().

- [ ] Consolidate repeated UI rendering patterns
  Description: drawMainMenu(), drawNamingKeyboard(), drawFileBrowser() duplicate layout logic. Create generic menu renderer.

### Performance & Memory
- [ ] Replace String class with char buffers
  Description: Using String for FUDI parsing and file buffers is wasteful on microcontroller. Use fixed-size char arrays or preallocated buffers.

- [ ] Optimize getFudiArg() to avoid rescans
  Description: Current implementation rescans string from start for each argument. Create single-pass tokenizer instead.

### Code Quality
- [ ] Extract magic numbers to named constants
  Description: Display coordinates (43, 11, 128, 64), pixel mappings, timing (400ms) scattered throughout. Centralize in header.

- [ ] Replace long if-else chains with command dispatch table
  Description: parseFudiCommand() has 12+ conditions. Use array of function pointers for FUDI commands.

- [ ] Add error handling for FUDI parsing and buffer overflow
  Description: No validation if file buffer overflows (MAX_FILES=30). No recovery if FUDI parse fails.
